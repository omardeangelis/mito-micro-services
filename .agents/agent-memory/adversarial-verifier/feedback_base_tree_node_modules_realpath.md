Symlinking `wt-dev/node_modules` as a whole to the source worktree makes the relative `@mito/*` links resolve (realpath) into the SOURCE worktree: base-tree tests then import head production code and fail with Cause-shape / "reading 'build'" / ServerLive-vs-serverLayer errors that look like regressions. Build `node_modules` as a real dir with per-entry symlinks, and `cp -R -P` the `@mito` dir and each `apps/*|packages/*/node_modules`, so relative links stay inside the tree. Check `readlink node_modules/@mito/server` then `ls` it inside the tree.

Also: the scratchpad is shared by parallel passes (load average 100): name outputs in a pass-unique folder (`vf-vN/`), run only the changed test files with `--maxWorkers=3` (a full-suite run timed out on hooks), and avoid `rm` of `$VAR/...` paths (blocked); use `git worktree remove --force`.

**Why:** 2026-10-27 PR 4 effect-4 v7: first dev run showed 76 "failures" that were all mixed-tree artifacts.

**How to apply:** any base-vs-head JSON-reporter comparison. fullName includes the describe title, so map renamed describe titles before diffing test names. Related: [[write-parity-scratch-copy-probe]].
