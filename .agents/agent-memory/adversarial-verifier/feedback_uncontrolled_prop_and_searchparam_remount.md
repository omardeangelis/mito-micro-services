A fix of the form "the page reads `?tf=` once with `parseTimeFrame` and passes it as a prop to the selector" is tested with mount-time tests (page test with a fake selector, selector test with one render). Both pass while the selector (`Radix Select defaultValue={prop}`, uncontrolled) shows a stale value after a soft navigation. Next 14.2 `layout-router.js` keys the page's `TemplateContext.Provider` with `createRouterCacheKey(segment, true)`, which drops the search params, so the page subtree is NOT remounted when only `?tf=` changes (sidebar `<Link href="/dashboard/">` from `?tf=90d`, Back/Forward). Probe: out-of-tree vitest, `render(<Sel timeframe="90d"/>)` then `rerender(<Sel timeframe="30d"/>)`, read `getByRole("combobox").textContent` (got `90d`).

**Why:** the analytics-effect AC11 test pair proved only the hard-load case; the numbers (server, 30d) and the selector (client state, 90d) disagree on the soft-nav path, which is the S8 symptom the AC meant to remove. The old code (`useSearchParams` + `defaultValue`) had the same flaw, so it is not a regression but still an unmet intent.

**How to apply:** for any "URL value -> uncontrolled control" fix, ask for a rerender test and for `value=`/`key=` on the control; mark the browser check (click the nav link from `?x=a`, press Back) as the human step when no server is available.

**Second pass (the fix was `key={timeframe}` on the Select, plus a rerender test):** the rerender test kills the no-key mutant, but check what a key remount costs. (a) The trigger is a NEW DOM node when the nav commits: after pick, Radix returns focus to the trigger, then `activeElement` becomes BODY (probe: `userEvent` open + pick, wait 50 ms, `rerender` with the new prop, compare `getByRole("combobox")` node identity and `document.activeElement`); base code kept focus. A derived-state variant (`value={shown}`, `if (prop !== seen) { setSeen(prop); setShown(prop) }`) passes the same probes with focus kept. Next's own `domNode.focus()` after a push hits the non-focusable `<main>`, so it does not rescue it. (b) Next 14.2 `action-queue.js` DISCARDS a pending navigate when a new navigate/restore arrives, so a pick whose navigation is superseded never changes the prop: if the landing URL parses to the pre-pick value (sidebar "Dashboard" while the prop is `30d`), the key never changes and the Select keeps the pick (selector 90d, numbers 30d). Narrow window (RSC fetch latency); say so and give the human check (throttle, pick, click the link at once). (c) The committed selector test never picks, so 4/4 mutants (no `router.push`, constant `tf`, no setter, no subscription) survive: copy the committed test to scratch and point its import at each mutant file to prove it (grep the diff of mutant vs original first).

Also seen in that pass: (1) `z.enum(OPTIONS)` -> `z.string()` on a procedure input survived 131 tests because nothing posts an invalid value to the procedure; prove the 400 with a real-backend HTTP probe (hono `serve` + `backendLink` + PGlite, reuse `backendLink.db.test.ts` as the template) and ask for a test. (2) A calendar-day window mutant (`setDate(getDate()-N)`) survives with `TZ=UTC` and dies under Europe/Rome and America/Los_Angeles: windows tests are not in the utc/rome projects, so it is invisible in a UTC CI. (3) A date-format fixture made only of winter instants cannot tell `Europe/Rome` from a fixed `Etc/GMT-1`; add a summer instant at 22:30Z. (4) On macOS a mktemp path needs `/private` + path in the vitest `dir` and `fs.allow`, else "Failed to load url". Related: [[day-rule-tests-and-tz-matrix]], [[out-of-tree-vitest-probe]], [[real-handler-client-probe]].

**Third pass (fix = controlled `value={shown}` + render-phase derived reset `if (prop !== seenProp) { setSeenProp(prop); setShown(prop) }`, tests: pick->push once with `tf=90d`, in-flight keeps pick, focus identity after landing rerender):** a 21-mutant battery in a `git archive` copy (key remount, no prop sync, value from prop, no setShown on pick, no setter, no push, constant tf, compare to `shown` instead of last-seen prop, last-seen never updated, no-deps effect resync, double push, no unsubscribe, defaultValue+key) killed 19; the 2 survivors were equivalent (effect-on-[prop] resync; last-seen initial value). Useful kill reasons: the no-unsubscribe mutant dies only on `push` called 6 times (subscriptions leak across tests through the module-level zustand store), the `key` mutants die on node identity / `activeElement === body`. Stress: 8 parallel runs with `--sequence.shuffle` stayed green (the 50 ms real wait for Radix focus return is not flaky). Probes that passed: re-pick of the value the store still holds after a link reset (zustand `set({timeframe})` always notifies because the partial is a new object), keyboard pick keeps focus on the trigger. Only residue: Next `action-queue.js` sets `pending.discarded = true` on a new navigate/restore, so pick then link/Back leaves `shown` on the pick while the prop never changes (probe P3 shows `90d` with page `30d`); the author tracked it as a FOLLOW-UP, needs the browser check to prove. Two quick picks landing out of order cannot happen (the first is discarded), so do not report the flicker.
